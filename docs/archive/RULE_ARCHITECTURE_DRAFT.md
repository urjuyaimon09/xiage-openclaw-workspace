## 1. 背景与目标

**目标：** 建立一套可执行、可监督的规则体系，支撑后续四个业务文档（二到五阶段）的制定与运行。

**核心原则：**
- 一阶段（规则体系）是"宪法"，规定组织、职责、基本规则
- 二到五阶段是"具体业务部门"，在一阶段框架下运行
- 规则体系必须落到执行层，不能只写文字

---

## 2. 三类规则分类（核心概念）

现有文档管了三种不同性质的东西，必须分开处理：

| 类型 | 定义 | 约束力 | 监督方式 |
|------|------|--------|---------|
| **规则型** | 有明确执行/违反边界，违反即产生错误 | 强制，必须执行 | 检查是否执行到位 |
| **知识型** | 记忆、上下文，违反产生坏结果但不报错 | 参考，灵活处理 | 不检查，只在错误时回顾 |
| **流程型** | 有明确先后顺序和条件分支 | 强制，必须按顺序执行 | 检查流程是否完整执行 |

**现行问题：** 三类混在同一个文档体系里，用同一套监督逻辑，效果差。

---

## 3. 三层架构

### 3.1 立法层（规则制定）

| 角色 | 组成 | 职责 |
|------|------|------|
| 提案者 | 坚果、我、网络信息 | 提出规则需求和草案 |
| 审议者 | 坚果、我 | 讨论规则内容、范围、落地方式 |
| 批准者 | **坚果（最终权限）** | 坚果说"同意"才生效 |

**规则分类（立法层产出）：**
- **约束型**：必须执行，违反产生错误 → 进入执行日志监督
- **参考型**：灵活处理，违反产生坏结果但不报错 → 不强制监督

### 3.2 执法层（规则执行）

**核心机制：Skill 前置检查**

规则落地不走五层架构（成本高），走 Skill 选择层：

```
用户输入 → Skill选择 → 前置检查函数 → 规则检查 → Skill执行
                                  ↓
                            通过 → 执行
                            违反 → 记录日志 + 上报
```

**规则落地方式：**
- 约束型规则：绑定前置检查函数，违反自动拦截
- 参考型规则：写入文档，触发时读取，不强制拦截

### 3.3 监督层（规则监督）

**两层监督：**

| 层 | 时机 | 机制 |
|---|------|------|
| 事中 | Skill执行前 | 前置检查函数，发现违规立即记录 |
| 事后 | 每周五评估时 | 检查执行日志，输出问题摘要到评估报告 |

**反馈闭环：**
- 问题日志 → 每周五汇总 → 立法层讨论 → 决定改规则还是改执行

## 4. 第一步：执行日志（立即可执行）

执行日志是整个监督层的基础。没有它，监督是空谈。

### 4.1 日志格式

文件：`~/.openclaw/workspace/rules-execution-log.jsonl`（append-only）

每条记录：
```json
{
  "timestamp": "2026-03-26T11:13:00+08:00",
  "rule": "核心文档修改必须先方案后授权",
  "trigger": "AGENTS.md edit 调用",
  "result": "pass|fail|skip",
  "detail": "SKILL_LIFE.md修改，已获授权",
  "session": "feishu-group"
}
```

### 4.2 需要日志的检查点（第一步，先记录3个）

| 规则名 | 检查点位置 | 结果判定 |
|--------|-----------|---------|
| 核心文档修改必须先授权 | edit工具调用前 | 检查是否有「同意变更并升级版本」触发词 |
| 代码修改必须先授权 | exec工具调用前（x 哥代码） | 检查是否有「同意，生效」触发词 |
| 技能使用后必须记录 | Skill执行完成后 | 检查是否调用了recordUsage |

### 4.3 执行日志函数

```javascript
// 伪代码
function logRuleCheck(ruleName, trigger, result, detail, session) {
    const entry = { timestamp, rule, trigger, result, detail, session };
    fs.appendFileSync(LOG_FILE, JSON.stringify(entry) + '\n', 'utf8');
}
```
