# TASK_ACCEPTANCE_MODEL.md — 任务承接模型

> 六阶段意识循环第三环：感知 → 需求 → 承接 → 计划 → 执行 → 反馈
> 版本：v2.0.0

---

## 一、模型定位

```
需求模型（带执行目标分解）
    ↓
任务承接模型
    ↓ 承接方案
计划模型（新建）
    ↓
执行模型
```

**核心问题：** 需求来了，我们能不能接？怎么接？值不值得接？

---

## 二、模型架构

```
需求输入
    ↓
复杂度评估
    ↓
┌─────────────────┬─────────────────┐
│  轻量承接路径    │   重量承接路径   │
│  （L1 简单）    │   （L2/L3 复杂）│
└─────────────────┴─────────────────┘
    ↓                    ↓
需求具体化            能力边界评估
+ 承接方案            + IPD六阶段
+ 快速执行            + 商业账计算
         ↓                    ↓
         └────────┬───────────┘
                  ↓
            承接方案输出
                  ↓
            计划模型（制定WBS/里程碑/风险预案）
```

**注：** 「启动规划阶段」（WBS/里程碑/风险预案）已迁移至 PLAN_MODEL.md，本模型仅输出承接方案。

## 三、复杂度评估（入口层）

### 3.1 评估维度

| 维度 | 评估内容 | 影响 |
|------|---------|------|
| 资源投入 | 需要多少时间/算力/成本？ | 低于阈值 → 轻量 |
| 可逆性 | 错了能回退吗？ | 不可逆 → 重量 |
| 依赖度 | 依赖其他需求/外部条件吗？ | 有强依赖 → 重量 |
| 创新度 | 全新领域还是熟悉领域？ | 全新 → 重量 |
| 影响力 | 对五层需求的影响程度？ | 高影响 → 重量 |

### 3.2 复杂度分级

| 等级 | 条件 | 路径 |
|------|------|------|
| **L1 简单** | 资源少 + 可逆 + 无依赖 | 轻量承接 |
| **L2 中等** | 资源中等 或 有部分依赖 | 简化IPD |
| **L3 复杂** | 高资源 或 不可逆 或 强依赖 或 高影响 | 完整IPD |

### 3.3 快速判断

```
资源投入 < 2小时？可逆？无外部依赖？→ L1 轻量
不满足L1但影响可控？→ L2 简化
不满足L2？→ L3 完整IPD
```

## 四、轻量承接路径

### 4.1 触发条件

L1 简单需求 + DEMAND.md 中重要度=低/中

### 4.2 流程

```
需求确认 → 方案设计 → 承接方案输出 → 计划模型
```

**需求确认：**
- 识别验收条件（可测试/可观测）
- 验收条件模糊 → 反馈需求方澄清

**方案设计：**
- 评估能力边界
- 确定执行方式：虾哥自执行 / 指导+坚果执行 / skill自动化

**承接方案输出：**
- 触发词：「进入计划」
- 输出承接方案 → PLAN_MODEL

## 五、重量承接路径（L2/L3）

### 5.1 IPD六阶段（参考华为IPD流程）

#### Phase 1：概念阶段（CDCP）

**目标：** 回答"要不要做"

**关键活动：**
1. 需求分析：马斯洛层级映射、影响范围
2. 市场/机会分析：感知模型输入（趋势机会在哪里）
3. 概念设计：初步方案构思
4. 初步商业评估：粗算市场规模、投入产出比

**输出：** 概念决策包（要不要做）

**决策点：** CDCP（Concept Decision Checkpoint）

---

#### Phase 2：计划阶段（PDCP）

**目标：** 回答"怎么做"

**关键活动：**
1. 系统设计：详细方案
2. 资源落实：虾哥能力评估、坚果时间评估
3. 能力gap分析：现有能力 vs 需要能力
4. 完整商业计划：商业账计算（见下节）

**输出：** 商业计划书（怎么做、投入多少、预期回报）

**决策点：** PDCP（Plan Decision Checkpoint）

---

#### Phase 3：开发阶段

**目标：** 产品设计与实现

**关键活动：**
1. 详细设计：方案细化
2. 执行开发：虾哥主执行 或 指导+坚果执行
3. 单元测试 / 集成测试
4. 技能补齐（如需要新skill）

**输出：** 可测试的解决方案

**技术评审：** TR2 / TR3

---

#### Phase 4：验证阶段

**目标：** 验证方案有效性

**关键活动：**
1. 系统验证：DEMAND.md 验收条件对照
2. 效果评估：真的满足了需求吗？
3. 迭代优化：如不满足 → 返回开发

**输出：** 验证报告

---

#### Phase 5：发布阶段

**目标：** 方案固化，可重复执行

**关键活动：**
1. 方案文档化
2. 流程固化（如果需要自动化）
3. 经验沉淀到 lessons.md

**输出：** 完整交付文档

---

#### Phase 6：生命周期阶段

**目标：** 持续优化 or 平稳退出

**关键活动：**
1. 效果跟踪：是否持续满足需求
2. 优化迭代：如需求变化
3. 退出计划：如不再需要

**输出：** 生命周期报告

**注：** IPM六阶段结束后进入 PLAN_MODEL 制定执行计划。

## 六、商业账计算（IPD核心）

> 先算商业账，再做技术活

### 6.1 核心原则

```
商业账 = 收益 - 投入

收益 > 投入 → 值得做
收益 < 投入 → 不值得做
```

---

### 6.2 投入计算

```
总投入 = 算力成本 + 坚果时间成本 + 外部成本
```

**算力成本（虾哥核心资源）：**

| MiniMax套餐使用率 | 策略 | 说明 |
|------------------|------|------|
| < 70% | 积极承接 | 用算力换价值，追求用完套餐 |
| 70% ~ 90% | 筛选承接 | 优先接ROI>1.5的需求 |
| > 90% | 严格控制 | 只接ROI>3的需求，保留余量 |
| 接近100% | 暂停新需求 | 优先完成现有，停止接新 |

**算力成本计算：**
```
算力成本 = 实际消耗token × 套餐单价
套餐单价 = 月费用 ÷ 月额度token
```

**坚果时间成本：**
```
坚果时间成本 = 投入小时数 × 小时工资折算
```

**外部成本：**
```
外部成本 = 第三方API费用 + 工具/Skill成本（如有）
```

---

### 6.3 收益评估

| 收益类型 | 说明 | 量化方式 |
|---------|------|---------|
| 算力利用率提升 | 用完套餐 = 省钱（边际成本趋零）| 节省的边际成本 |
| 效率提升 | 节省了多少时间 | 小时数 × 工资折算 |
| 五层需求贡献 | 满足哪个层级？满足多少？ | 定性 + 权重 |
| 风险降低 | 缓解了哪个风险？ | 定性 + 影响程度 |
| 能力积累 | 新增skill/知识？ | 长期价值 |

---

### 6.4 ROI计算

```
ROI = 收益总价值 ÷ 总投入

收益总价值 = 量化收益 + 定性收益（权重化）
```

---

### 6.5 决策标准

| ROI | 决策 |
|-----|------|
| ROI > 3 | 强烈建议做 |
| ROI 1.5 ~ 3 | 可以做 |
| ROI < 1.5 | 慎重考虑 |
| ROI < 1 | 不做 |

**算力约束叠加：**
```
算力 < 70%：ROI > 1 即可承接（用算力换价值）
算力 70%~90%：ROI > 1.5 才承接
算力 > 90%：ROI > 3 才承接
```

## 七、能力边界评估

### 7.1 评估框架

```
现有能力（SOUL + CAPABILITY_LIFE）
    ↓
所需能力（需求拆解后）
    ↓
能力 Gap
    ↓
Gap补齐方案
```

### 7.2 Gap补齐方式

| Gap类型 | 补齐方式 |
|---------|---------|
| skill缺失 | xiage-skills搜索安装 |
| 知识缺失 | 感知模型抓取学习 |
| 工具缺失 | 自行搭建skill |
| 坚果执行能力缺失 | 指导+培训 |

### 7.3 能力-趋势机会交集

```
感知到的趋势机会
    ↓
评估：我们有这个能力吗？
    ↓
有 → 进入承接评估
没有 → 评估gap + 补齐成本
    ↓
gap可补齐 → 进入承接（时间+成本增加）
gap不可补齐 → 标记为"待观察"，暂不承接
```

## 九、触发索引（Agent调用）

| 触发词 | 效果 |
|--------|------|
| 「需求承接」 | 需求 → 复杂度评估 → 路径选择 |
| 「轻量承接」 | 直接进入轻量路径（省去评估） |
| 「IPD承接」 | 直接进入重量IPD路径 |

| 「能力评估」 | 当前能力边界评估 |
| 「补齐能力」 | Gap分析 + 补齐方案 |
| 「算力状态」 | 返回当前算力使用率和承接策略 |
| 「算账」 | 输入收益/投入 → 计算ROI |
| 「进入计划」 | 承接方案输出 → 触发 PLAN_MODEL |
