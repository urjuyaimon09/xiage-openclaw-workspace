# TASK_EXECUTION_MODEL.md — 执行实施模型

> 五模型第四/五环：计划 + 执行 + 收尾（合并为一个模型）
> 版本：v1.0.0

---

## 一、模型定位

```
需求承接模型（TASK_ACCEPTANCE_MODEL）
    ↓ 立项（目标/方案/ROI）
执行实施模型（TASK_EXECUTION_MODEL）
    ↓
感知模型反馈闭环（执行中发现的新信息 → 感知模型）
```

**核心问题：** 如何高效执行已立项的任务，实现交付并积累能力？

---

## 二、模型架构

```
执行实施模型
├── 一、启动规划阶段
│   ├── 目标锁定
│   ├── WBS任务分解（标注执行主体）
│   ├── 里程碑计划
│   └── 风险预案
│
├── 二、执行阶段
│   ├── 任务派发

│   ├── 进度追踪（自动状态更新）

│   └── 感知反馈（→ 感知模型）
│
└── 三、收尾阶段
    ├── 验收确认
    ├── 复盘沉淀

    └── 项目结项
```

## 三、启动规划阶段

### 3.1 目标锁定

**输入：** 来自需求承接模型的立项输出
- 目标描述
- 验收条件
- 方案概要
- ROI评估

**动作：**
1. 确认理解目标（模糊则追问）
2. 锁定交付范围
3. 确认时间约束

**输出：** 锁定的项目目标

---

### 3.2 WBS任务分解

> 核心特点：标注执行主体（AI / 坚果）

**格式：**

```
WBS分解格式：
任务编号 | 任务描述 | 执行主体 | 完成标准 | 依赖关系

示例：
T1 | 信息收集 | AI | 输出收集报告 | 无
T2 | 方案设计 | AI | 输出方案文档 | T1
T3 | 坚果审核方案 | 坚果 | 确认或反馈 | T2
T4 | 执行落地 | AI | 完成变更 | T3
T5 | 坚果验收 | 坚果 | 确认交付 | T4
```

**执行主体分类：**

| 标识 | 含义 | 说明 |
|------|------|------|
| AI | 虾哥自执行 | 虾哥可自主完成，无需干预 |
| 坚果 | 坚果执行 | 坚果亲自操作，虾哥辅助 |
| 指导+坚果 | 虾哥指导，坚果执行 | 坚果为主，虾哥提供方案 |
| 共同 | 双方协同 | 需要双方配合 |

---

### 3.3 里程碑计划

**格式：**

```
里程碑 | 计划日期 | 实际日期 | 状态 | 备注
M1 | 2026-04-15 | - | 计划 | 方案设计完成
M2 | 2026-04-16 | - | - | 坚果审核完成
M3 | 2026-04-17 | - | - | 执行完成
M4 | 2026-04-18 | - | - | 验收交付
```

**里程碑设置原则：**
- 每个里程碑对应一个可验证的交付物
- 坚果参与的节点必须设置里程碑
- AI任务可连续执行，设置检查点即可

---

### 3.4 风险预案

**格式：**

```
风险编号 | 风险描述 | 概率 | 影响 | 预案 | 触发条件
R1 | 坚果时间不足 | 中 | 高 | 压缩范围或延后 | 坚果反馈无时间
R2 | AI任务技术障碍 | 低 | 中 | 求助社区/调整方案 | 执行失败
R3 | 外部依赖延迟 | 低 | 中 | 跳过该模块 | 第三方未响应
```

## 四、执行阶段

### 4.1 任务派发

**触发：** 「开始执行」

**动作：**
1. 按WBS顺序派发任务
2. 明确每个任务的执行主体
3. AI任务 → 自动进入执行队列
4. 坚果任务 → 通知坚果（明确做什么、验收标准、截止时间）

**通知格式（坚果任务）：**

```
📋 任务通知

任务：T3 - 坚果审核方案
内容：审核附后的方案文档，决定是否通过
截止：2026-04-16 18:00
验收标准：明确「通过」或「反馈修改意见」

[方案文档链接]
```

---

### 4.2 自主推进

**AI任务执行规则：**
- 虾哥领取AI任务后自主执行
- 不需要坚果确认每个步骤
- 完成后自动更新里程碑状态

**执行过程中：**
- 遇到障碍 → 先尝试解决（查文档/搜索/查skill）
- 解决不了 → 记录问题，等待坚果决策
- 发现新信息 → 触发感知反馈

---

### 4.3 进度追踪

**自动状态更新机制：**

| 触发时机 | 更新内容 |
|---------|---------|
| AI任务完成 | 里程碑状态 → 完成 |
| 坚果确认反馈 | 里程碑状态 → 完成 或 进入下一任务 |
| 计划日期到达 | 里程碑状态 → 延期（如未完成）|

**状态推送规则：**

| 场景 | 动作 |
|------|------|
| 一切正常 | 静默，不打扰 |
| AI任务完成 | 推送完成通知（可选）|
| 坚果任务到期前1天 | 提醒坚果 |
| 坚果任务到期未完成 | 再次提醒 |
| 里程碑延期 | 通知坚果，说明原因 |

---

### 4.4 纠偏机制

#### AI任务纠偏（虾哥自主）

**触发：** AI任务执行中发现偏差

**规则：**
- 小偏差（不影响目标）→ 虾哥自主调整
- 中偏差（可能影响目标）→ 虾哥调整 + 通知坚果
- 大偏差（显著影响目标/ROI/时间）→ 通知坚果，等待决策

**偏差判断标准：**

| 偏差类型 | 判断 | 处理方式 |
|---------|------|---------|
| 范围偏差 | 实际做的东西超出WBS范围 | 停止 + 通知坚果 |
| 质量偏差 | 产出质量低于验收标准 | 重做 + 分析原因 |
| 时间偏差 | 预计完成时间超过里程碑 | 提前预警 + 调整方案 |
| 资源偏差 | 算力消耗超出预期 | 评估 + 调整计划 |

---

#### 坚果任务纠偏（坚果决策）

**触发：** 坚果任务到期未完成或反馈有问题

**通知格式：**

```
⚠️ 需要坚果决策

任务：T3 - 坚果审核方案
原定截止：2026-04-16 18:00
当前状态：未完成

选项：
A. 延后到 [新日期]（影响后续里程碑）
B. 压缩范围（砍掉部分审核内容）
C. 协助（虾哥帮忙做，坚果确认）

请回复 A/B/C 或您的方案。
```

---

### 4.5 感知反馈

> 执行过程中发现的新信息 → 反馈给感知模型

**反馈触发条件：**

| 发现内容 | 反馈动作 |
|---------|---------|
| 新风险信号 | → 感知模型风险库 |
| 新机会信号 | → 感知模型机会库 |
| 技术突破/障碍 | → 感知模型 + capability_map |
| 坚果状态变化 | → 感知模型（协作边界更新）|

---

## 五、收尾阶段

### 5.1 验收确认

**触发：** 所有AI任务完成 + 坚果确认交付

**动作：**
1. 对照原始需求，验证验收条件
2. 坚果确认（或提出未满足项）
3. 未满足 → 返回执行阶段补充
4. 满足 → 进入复盘

**验收标准确认：**
```
原始验收条件：
[ ] 条件1：可测试/可观测的具体标准
[ ] 条件2：...

实际完成情况：
[✓] 条件1：已完成，证据：...
[✓] 条件2：已完成，证据：...

坚果确认：✓ 通过 / ✗ 需补充
```

---

### 5.2 复盘沉淀

**触发：** 「复盘」或坚果确认验收后自动触发

**复盘内容：**

```
#### [项目名称] 复盘报告

**原始目标：**
- ...

**实际结果：**
- 完成：...
- 未完成：...

**经验教训：**
- 做得好的：...
- 需要改进的：...

**能力更新：**
- 新增skill：
- 新增知识：
- 更新capability_map：

**下一步建议：**
- ...

**标签：** #复盘 #项目名
```

**更新文件：**

| 文件 | 更新内容 |
|------|---------|
| lessons.md | 做得好的 + 需要改进的 |
| capability_map.md | 新增能力 + 能力等级更新 |
| DEMAND.md | 需求状态 → 已完成 |

---

### 5.3 项目结项

**触发：** 复盘完成

**动作：**
1. 生成结项报告
2. 归档项目文件
3. 更新感知模型（项目关闭）
4. 通知坚果项目正式关闭

```
上游：TASK_ACCEPTANCE_MODEL
    ↓ 立项输出
TASK_EXECUTION_MODEL
    ↓ 执行 + 感知反馈

    ↓
下次感知循环
```

## 八、执行主体标注规则（附录）

> WBS分解时必须标注执行主体，便于责任认定和进度追踪

| 标识 | 执行主体 | 坚果介入程度 | 典型任务 |
|------|---------|------------|---------|
| AI | 虾哥 | 无需介入 | 信息收集/方案生成/自动化执行 |
| 坚果 | 坚果 | 全程 | 需要坚果权限的操作/验证/确认 |
| 指导+坚果 | 坚果（主导）| 虾哥提供方案 | 坚果执行但需要指导的操作 |
| 共同 | 双方协同 | 按需 | 需要双方配合的任务 |
