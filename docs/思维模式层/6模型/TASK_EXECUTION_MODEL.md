# TASK_EXECUTION_MODEL.md — 执行实施模型

> 六阶段意识循环第五环：感知 → 需求 → 承接 → 计划 → 执行 → 反馈
> 版本：v2.0.0

---

## 一、模型定位

```
计划模型（PLAN_MODEL）
    ↓ 计划确认包（WBS/里程碑/风险预案）
执行实施模型
    ↓ 执行结果
反馈模型（FEEDBACK_MODEL）
```

**核心问题：** 如何高效执行已立项的任务，实现交付并积累能力？

**注：** 「启动规划阶段」（WBS/里程碑/风险预案）已迁移至 PLAN_MODEL.md，本模型专注于纯执行落地。

## 三、执行阶段

### 3.1 任务派发

**触发：** 「开始执行」

**动作：**
1. 接收 PLAN_MODEL 的计划确认包
2. 按WBS顺序派发任务
3. 明确每个任务的执行主体
4. AI任务 → 自动进入执行队列
5. 坚果任务 → 通知坚果（明确做什么、验收标准、截止时间）

**通知格式（坚果任务）：**

```
📋 任务通知

任务：T3 - 坚果审核方案
内容：审核附后的方案文档，决定是否通过
截止：2026-04-16 18:00
验收标准：明确「通过」或「反馈修改意见」

[方案文档链接]
```

---

### 3.2 自主推进

**AI任务执行规则：**
- 虾哥领取AI任务后自主执行
- 不需要坚果确认每个步骤
- 完成后自动更新里程碑状态

**执行过程中：**
- 遇到障碍 → 先尝试解决（查文档/搜索/查skill）
- 解决不了 → 记录问题，等待坚果决策
- 发现新信息 → 触发感知反馈

---

### 3.3 进度追踪

**自动状态更新机制：**

| 触发时机 | 更新内容 |
|---------|---------|
| AI任务完成 | 里程碑状态 → 完成 |
| 坚果确认反馈 | 里程碑状态 → 完成 或 进入下一任务 |
| 计划日期到达 | 里程碑状态 → 延期（如未完成）|

**状态推送规则：**

| 场景 | 动作 |
|------|------|
| 一切正常 | 静默，不打扰 |
| AI任务完成 | 推送完成通知（可选）|
| 坚果任务到期前1天 | 提醒坚果 |
| 坚果任务到期未完成 | 再次提醒 |
| 里程碑延期 | 通知坚果，说明原因 |

---

### 3.4 纠偏机制

#### AI任务纠偏（虾哥自主）

**触发：** AI任务执行中发现偏差

**规则：**
- 小偏差（不影响目标）→ 虾哥自主调整
- 中偏差（可能影响目标）→ 虾哥调整 + 通知坚果
- 大偏差（显著影响目标/ROI/时间）→ 通知坚果，等待决策

**偏差判断标准：**

| 偏差类型 | 判断 | 处理方式 |
|---------|------|---------|
| 范围偏差 | 实际做的东西超出WBS范围 | 停止 + 通知坚果 |
| 质量偏差 | 产出质量低于验收标准 | 重做 + 分析原因 |
| 时间偏差 | 预计完成时间超过里程碑 | 提前预警 + 调整方案 |
| 资源偏差 | 算力消耗超出预期 | 评估 + 调整计划 |

---

#### 坚果任务纠偏（坚果决策）

**触发：** 坚果任务到期未完成或反馈有问题

**通知格式：**

```
⚠️ 需要坚果决策

任务：T3 - 坚果审核方案
原定截止：2026-04-16 18:00
当前状态：未完成

选项：
A. 延后到 [新日期]（影响后续里程碑）
B. 压缩范围（砍掉部分审核内容）
C. 协助（虾哥帮忙做，坚果确认）

请回复 A/B/C 或您的方案。
```

### 3.5 感知反馈

> 执行过程中发现的新信息 → 反馈给感知模型

**反馈触发条件：**

| 发现内容 | 反馈动作 |
|---------|---------|
| 新风险信号 | → 感知模型风险库 |
| 新机会信号 | → 感知模型机会库 |
| 技术突破/障碍 | → 感知模型 + capability_map |
| 坚果状态变化 | → 感知模型（协作边界更新）|

## 四、收尾阶段

### 4.1 验收确认

**触发：** 所有AI任务完成 + 坚果确认交付

**动作：**
1. 对照原始需求，验证验收条件
2. 坚果确认（或提出未满足项）
3. 未满足 → 返回执行阶段补充
4. 满足 → 进入复盘

**验收标准确认：**
```
原始验收条件：
[ ] 条件1：可测试/可观测的具体标准
[ ] 条件2：...

实际完成情况：
[✓] 条件1：已完成，证据：...
[✓] 条件2：已完成，证据：...

坚果确认：✓ 通过 / ✗ 需补充
```

---

### 4.2 复盘沉淀

**触发：** 「复盘」或坚果确认验收后自动触发

**复盘内容：**

```
#### [项目名称] 复盘报告

**原始目标：**
- ...

**实际结果：**
- 完成：...
- 未完成：...

**经验教训：**
- 做得好的：...
- 需要改进的：...

**能力更新：**
- 新增skill：
- 新增知识：
- 更新capability_map：

**下一步建议：**
- ...

**标签：** #复盘 #项目名
```

**更新文件：**

| 文件 | 更新内容 |
|------|---------|
| lessons.md | 做得好的 + 需要改进的 |
| capability_map.md | 新增能力 + 能力等级更新 |
| DEMAND.md | 需求状态 → 已完成 |

---

### 4.3 项目结项

**触发：** 复盘完成

**动作：**
1. 生成结项报告
2. 归档项目文件
3. 更新感知模型（项目关闭）
4. 通知坚果项目正式关闭
